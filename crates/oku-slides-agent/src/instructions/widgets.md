Creating a widget: a widget is a Typst file of the template pack; use widget_sources, widget_source, set_widget, remove_widget and preview_widget, in deck and template modes alike. Shape of a file kpi: #import "/oku-slides/lib.typ": widget, field, fields-stack, list-item, params as p, color-of, size-of, then #let widget = widget("kpi", params: (value: p.plain(), label: p.plain()), (args, ctx) => …); the declared name is the file name. Parameters: descriptors p.plain, p.rich, p.flag, p.number, p.choice, p.asset, p.slot, p.grid. Editable texts: field(ctx, "value", args.value), stacked with fields-stack. Colors and sizes: theme tokens (color-of(ctx.tokens, "accent"), size-of(ctx.tokens, "body")), never hard-coded values. Shared code: the _commun file, imported with #import "_commun.typ": …. Loop: write with set_widget, read the status and its diagnostics (line, column), look at preview_widget, fix. To put it in the deck: add_element with kind = the widget name. A slide widget declares category: "slide" (widget("name", category: "slide", params: …)); otherwise it is an element. In a descriptor, label: and default: are optional (p.plain(), p.plain(label: "Title", default: "…")). In templates mode, set a widget's test values with set_widget_trial; preview_widget without params uses them, and the user sees them in the widget's settings. Lists: p.list(item: (date: p.plain(), texte: p.plain()), item-label: "…", max: 8) for repeated items (timeline, KPIs, team); column types plain, rich, number, flag, choice, asset, or one nested p.list (one level only: a nested list has no list column), e.g. steps with sub-tasks: item: (titre: p.plain(), taches: p.list(item: (texte: p.plain()))). Render each item with list-item(ctx, "etapes", e, c => field(c, "date", e.date)); for an empty field use field(c, name, box(width: 3em, hide[0]), empty: true) so it stays editable. Render a nested item with list-item(c, "taches", x, cc => field(cc, "texte", x.texte)), passing the parent item's c. Never simulate a list with numbered params (date1, date2…). An absent list is empty; default only seeds a new object. Items have stable ids: edit them with edit_list(target, param, change) (change: insert(index?, id, values?), remove(item), move(item, to), set_field(item, field, value); you supply the id); for a nested list, param is etapes/<step id>/taches, or replace the whole list with set_param (null empties it). When add_element or add_slide creates a widget without your giving its items, pass "defaults": true to seed the list defaults; never when re-inserting or moving.
