## Lot B — Jeton MCP comparé en temps constant (t-696)

`require_bearer` (`crates/oku-slides-mcp/src/server.rs`) compare l'en-tête `Authorization` avec `==`.
Le condensat SHA-256 de l'attendu (`"Bearer <hex>"`) est calculé une fois au démarrage ; l'état du
middleware devient ce condensat (`[u8; 32]`, plus le jeton en clair) ; le reçu est haché depuis ses
octets bruts (`HeaderValue::as_bytes()`, plus de branche `to_str()`), et les deux condensats comparés
avec `==`, dans une fonction nommée. Sa doc dit pourquoi c'est sûr : `==` sur les condensats n'est pas
en temps constant, mais il ne révèle qu'un préfixe du condensat, inexploitable tant que le jeton est
aléatoire à haute entropie (32 octets de `getrandom`) ; la propriété temporelle n'est pas testable.
`sha2` en `.workspace = true` (0.10 ; aucune crate nouvelle dans Cargo.lock).
`crates/oku-slides-mcp/ARCHITECTURE.md` : la ligne sur le 401 mentionne la comparaison par condensat.
Tests de caractérisation (exception TDD déclarée : verts avant et après, le défaut est temporel), par
HTTP via le harnais : jeton exact accepté ; refusés : même longueur faux, préfixe du jeton, jeton plus
long d'un caractère, valeur vide, en-tête absent, `bearer` en minuscules, sans schéma, espace final,
octets non ASCII.
