# Packs and themes as tabs — lot 3: library pack tabs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A library pack (widgets or layouts) opens in its own window tab, seeded with the deck that opened it; closing the tab offers to move the opener to the version this tab wrote; a deck-only pack keeps today's workshop inside its deck tab.

**Architecture:** A tab says what it edits (`TabDocument`). `PackMode` gains a host: `Deck` (today's in-deck workshop) or `Tab` (a pack tab, whose deck beside the pack is a never-saved **preview deck** copied from the opener, without assets, that never adopts anything). One workspace request, `OpenPack`, routes: a library pack opens (or focuses) a pack tab right after the requesting tab; a deck-only pack enters the workshop in place, as today. A **lease**, kept per library, marks the library packs being edited (an awake pack tab or an in-deck workshop) so no other tab writes them meanwhile; an editor without the lease is read-only until it gets it. When a pack tab closes, the UI asks the workspace which deck opened it and, once the tab has closed, asks that deck tab to pin the exact version the pack tab wrote. Every deck recomputes its "Packs du deck" badge at its next snapshot after any library write. The existing workshop UI runs inside the pack tab. The persisted formats stay readable by the previous release: only pack tabs need the new one.

**Tech Stack:** Rust 2024 (snafu, speculoos, rstest, nextest, OpenDAL `Storage`; clippy `pedantic`, `missing_docs`, `rust_2018_idioms`), React/TypeScript (Bun), Playwright e2e, Fluent.

## Decisions taken from the reviews (binding)

- `Request::EditPack` of a library pack is **not** refused in a deck tab in this lot (lot 5 removes the request; the UI and the agent stop sending it in Tasks 4-5), unless the pack is leased. In a **pack tab**, `EditPack` and `ClosePack` are refused (`InPackTab`) — in the requests **and** in the pub methods `Session::edit_pack` / `close_pack` themselves — and no deck-only pack is ever entered.
- `PackHost` lives only in `views::PackMode.host` (persisted, shown); every place that rebuilds a `PackMode` carries the previous host (pack-to-pack switches and the rebuild after every save included); `TabInfo.document` of a pack tab is derived from it in `tab_info`, never written on its own.
- The preview deck carries the opener's deck value, the pack and theme versions its pins reach, and its fonts — **no assets, no registry**. It is installed through the shared `install_document`, never `load_document`: it never runs `adopt_pins` / `refresh_pack_updates` / `adopt_default_*`, and is persisted with `dirty: false`. The opener ends its deck-mode widget session (its draft is frozen) only once the gate has allowed the new tab, right before the seed is copied. The preview is persisted and resumed with the tab, without its opener (the ADR records why).
- **The lease.** A library pack is leased, per library, while an awake pack tab or an in-deck workshop edits it (held by its `Mode::Pack`); a tab restored after a restart takes it when it wakes, not before (K3: no dormant lease). The key is `(LeaseScope, pack)`, where `LeaseScope` is the resolved widgets and layouts directories of the library the editor writes (`PackLibrary::lease_scope(&self)`, computed once per library: the session reads its own library, so `set_pack_dirs` moves its scope with it; the workspace takes the requesting session's scope from `PackRoute::Tab { scope }` — `PackLibrary::user(&platform)` serves only `workspace_and_session_compute_one_scope`, which pins that they agree for a fresh tab session); a library without both directories (`PackLibrary::new(None, …)`, tests only) takes no lease and has no library pack. There is at most one lease per pack: `PackLease::try_take` (inside a `DRAFTS` scope) and `PackLease::acquire` (taking `DRAFTS` itself) both refuse a held pack. The registry stores the holder's label at the time the lease is taken (a later rename is not reflected: the ADR says so), so a refusal names the tab to the user, never to an agent. While P is leased, no other tab: writes P's widgets in deck mode, makes another version of P current, deletes P, enters a workshop of P, or opens a second editor of P — each refused with `PackOpenInTab`; a tab deleting the pack it itself edits (leased or not) is refused with `InPackTab` (J10, L3). The lease is checked against the id actually written (`manifest.id`), never a value passed beside it (L9): `adopt_session_version` refuses a manifest id other than `edit.pack` (save-as-new aside) before `draft_lock()`, and resume checks the `pack/` base's id, kind, `session_version` and `parent` for **both** hosts (N5). The two library writers of pack mode, `write_session_version` and `restore_session_version` (`pack_library.rs:52-83`), take the lease as a witness (`lease: Option<&PackLease>`, last argument) and refuse library-scoped files without a matching one (`LeaseMissing`; `restore_session_version` logs it with `tracing::error!` and writes nothing), so a path that skips `ensure_pack_lease` cannot write (N7). Adoption stays allowed: another deck may pin (and so freeze) a version the pack tab wrote; the tab's next save becomes a child version. Themes are not leased in this lot (lot 4). **A lease refused at resume never sets work aside** (J2): the tab is restored without a lease — a pack tab as a pack tab, an in-deck workshop as its workshop — with the notice `notice-pack-edited-elsewhere` naming the holder. Nor does a library pack deleted while its editor was dormant (N4, O3, O4): a pack tab or an in-deck workshop is restored **orphaned** — read-only for the session's life (an in-memory `orphaned` flag: a pack that comes back later, through a deck-mode write or a received deck, does not make it writable), its writes refused with `UnknownPack`, `notice-pack-deleted` set, `SavePack { as_new: true }` its way out, a workshop's `ClosePack` returning its deck with its unsaved work. The same path serves a library whose versions became unreadable (`current_version` answers `None` then, `library.rs:352-363`), so nothing is lost by a false "deleted". **An editor without a lease is read-only** (L1, replacing K1; scoped by M1): only the requests that write the edited pack — the explicit list `Request::writes_edited_pack()` — and the entry points that reach the library writers without `handle` (`adopt_session_version`, `Session::apply`, undo `replay`) call `ensure_pack_lease()`, which retries `PackLease::acquire` (holder: the tab's title); taken → stored in the mode and the request goes on as usual; still held → `PackOpenInTab`, nothing changed (the tab keeps its unsaved work, persisted as today). `ClosePack`, `EditPack`, `DeletePack`, the file saves (`Save`, `SaveCopy`, `Move`, `Merge`) and reads never ask for the lease and keep their own refusals (`InPackTab`, `EditingPack`), checked first; so a read-only workshop can always give its deck back. `SavePack { as_new: true }` needs no lease on the original (M3: the copy is a new pack and takes its own), the natural way out of a read-only tab. "Library pack" is decided everywhere by one helper, `is_library_pack(files)` = `!is_deck_only(files)` (`is_deck_only` at `pack_receive.rs:21`), on the files being written or entered (`settle_lease` runs right after `pack_base`, before `stored.files` moves and before `closure_with_files`, `pack_mode.rs:216-217`, and decides from `stored.files`; only `try_take` runs under `DRAFTS`); a library-scoped pack the library no longer lists is refused with `UnknownPack` before any pack-mode write (M4), so pack mode never writes a deleted pack back; deck-mode widget writes keep today's behavior and can recreate one (`write_deck_widgets` → `save_draft`; N6, recorded on t-1157). The state is two snapshot flags computed when the view is built (M5, N1, O1: fields of `EditingView`, never stored in the persisted `PackMode`): `editing.read_only` — the tab is orphaned (O3), or the library index no longer lists the pack or its base (P3, Q4), or the edited pack needs a lease (a library pack in a library with a lease scope), the mode holds none and another editor holds it — and `editing.leased` — the mode holds its lease or needs none. Once the holder closes, `read_only` turns false at the next snapshot but `leased` stays false until an editing request takes the lease. It never writes the library while another tab holds the lease: no unleased version, no `set_current`, no `Replace` of the holder's draft (`save_draft` would do both: `library_draft.rs:105-110`, `library.rs:506-519`), no resurrected pack. Once the holder closes, its next write takes the lease and writes as usual — the last writer's version becomes current (L2, accepted: two sequential editors; the ADR says so). Its prelude (closed workspace refused, `tab` resolved to its window, `UnknownTab` otherwise) is factored with `open_beside`'s into one helper. Steps (`focus_existing` = steps 1-2, `open_new` = steps 3-5):
1. Under the workspace lock only: the prelude; collect **every** non-dormant tab whose cached `document` is `Pack { pack }` (ready or busy), then the dormant ones, in window order, keeping at most 4 dormant ones (O10: a forged layout cannot make one open wake every entry; past them the live re-scan of step 3 decides). Release. No pending tab is ever made for an unknown tab or a vanished window.
2. For each candidate in turn: if the candidate is not `tab`, `ask(PackGate::Focus)` once (before the first candidate; false → return `Refused`, nothing woken or activated). `with_session(candidate, …)` (it returns `(Result<R>, bool)`, `workspace_session.rs:43`: the `bool` says the tab's info changed and is ignored: `with_session` already refreshes the info and saves the layout when it changed, `workspace_session.rs:66-80`; `let (r, _changed) = …; r??` everywhere below) (this wakes a dormant tab and refreshes its info): if its real `tab_info().document` is still `Pack { pack }`, call `open_widget_tab(w)` there when `widget` is given (`UnknownWidget` → returned, nothing activated, opener unchanged); after `with_session` returns, take the lock: if the candidate is gone, go on with the next one; otherwise `activate`, and when `retarget` and `tab` is a deck tab (cached document `Deck`) still present, set the candidate's `opener = Some(tab)`; `save_layout`, release, return `Focused(candidate)` — or `Here { tab, entered: false }` when the candidate is `tab` itself. A candidate that is not a pack tab after waking, or whose wake fails, is skipped (a failure logged with `tracing::warn!`).
3. No candidate held → `with_session(tab, |s| s.route_pack(pack, widget))`: `Here { entered }` → return `Here { tab, entered }`. `Tab { scope, name }` → `ask(PackGate::NewTab)` (only the opening lock held): false → return `Refused` (nothing changed anywhere). Then `PackLease::acquire(&scope, pack, &name, &name)` **before** any change to the opener (J7): refused → re-scan once under the workspace lock with **live** infos (each non-dormant slot through `try_lock` + `tab_info()`, a busy one by its cached document): a pack tab of P found → step 2 on that one tab, **without asking again** (the `NewTab` answer covers it), return its outcome; none → return the refusal (an in-deck workshop, or a pack tab of another workspace in this process, holds P; the opener is untouched). Then `with_session(tab, |s| s.take_preview(pack))` (ends the deck's widget session, copies the seed); a failure — `tab` closed meanwhile (`UnknownTab`), or the pack no longer a library target — returns it and the lease drops. Then take the workspace lock, re-resolve `tab`'s window: `tab` gone → its window if it still exists, with `TabPlace::End` and no opener, else the focused window; build `pending(window, Opening::Pack { pack, widget }, TabPlace::After(tab))`, release; the seed and the lease stay locals.
4. `pending.build_pack(*seed, lease)` outside the lock: a fresh session (`tab_session`), then `init_pack_tab(seed, lease, pack, widget)` (the widget sub-tab is set here). A failure drops the lease with the arguments: nothing is left leased.
5. `finish` re-checks under the lock, calling no blocking or mutating session method (pre-split before the change: `fn resolve_place(&self, window: Option<String>, place: TabPlace) -> (Option<String>, TabPlace, Option<String>)` returns the window, place and opener, so `finish` stays under `too_many_lines`): workspace closed → refuse (the new session goes to `Trash`, which `finish` empties before it returns, so the lease is freed before the refusal reaches the caller); the window vanished → the focused window (today's rule), opener `None`; the anchor closed while its window remains → `TabPlace::End`, opener `None`; the anchor moved to another window but exists → `TabPlace::End`, opener kept. `TabPlace::Replace(r)` whose pristine check now fails → `TabPlace::End`. Otherwise insert at `position(after) + 1`, computed under this lock from that window's `tabs`, set `Tab.opener = Some(after)`, activate, `save_layout`; return `Opened(new)`. Once the tab is inserted, `open_pack_with` never returns `Err`: it keeps `pending.id` before calling `finish`, and on an `Err` from `finish` checks under the lock whether that id is in `w.tabs` — if so, logs the error and returns `Opened(id)`, so an agent's claim is never released for a tab that exists. There is no pack dedupe in `finish`: the opening lock and the single lease make a second pack tab of P impossible.
- **No dormant lease** (K3). A tab restored dormant holds nothing; when it wakes, `finish_pack_restore` acquires the lease or restores it without one (J2), read-only until it gets it (L1). Entries are restored in layout order; an entry without cached `info` resumes at once (`workspace_resume.rs:208-217`) and so acquires first.
- **Closing a pack tab** (`change()`'s `Close` arm, not `detach`): before `detach`, capture whether the closed tab was its window's active tab and its `opener`; after `detach`, if it was active and the opener is still a tab of the same window, set `win.active` to the opener; otherwise today's neighbour rule. Pure layout. `Slot::stop_resume` (l.109, run by `Trash::empty` after the workspace lock is released) now turns a `Ready` slot into `Closed(id)` too, after calling the session's `stop_resume()`, so a stale `with_session` holding the slot's `Arc` gets `UnknownTab` instead of writing. Known limit (P2 dropped, t-1206): `Trash::empty` still `relock`s a busy slot, so a discard close of a tab whose session is stuck waits until the stuck call returns, and its pack stays leased until then. Closing a tab never touches another tab's session (badges are lazy).

/// What a pack-tab claim answered.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum Reserve {
    /// The claim is held for this turn.
    Granted,
    /// The call's turn is not the open one, or the hub closed.
    NotThisTurn,
    /// This turn already claimed another pack.
    Taken,

    /// The turn that claimed it.
    turn: u32,
    /// The pack it opens.
    pack: Uuid,
