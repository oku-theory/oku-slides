# Packs and themes as tabs — lot 4: theme tabs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A library theme opens in its own window tab, whose pile holds read-only specimen slides (one per layout of the built-in Essentiel) rendered with the theme draft, edited with today's theme panel and saved through the library's draft rule; the theme draft leaves pack mode entirely.

**Architecture:** A tab says it edits a theme (`TabDocument::Theme`). A theme tab's session is `Mode::Theme`: its working document is a **specimen deck** (Essentiel's layouts at their example values, `base` and `essentiel` built-ins pinned, no theme, the draft as its tokens), so today's draft code (`theme_edit.rs`, `theme_draft.rs`, `theme_extends.rs`, `theme_panel.rs`) moves from `Mode::Pack` to `Mode::Theme` almost unchanged: tokens are still `SetToken` ops on the working deck, undo is still Loro's, base changes still ride `DRAFT_SWITCH_VAR`. Saving goes through `Library::draft_write` / `save_draft` under `draft_lock` (a draft is replaced in place until a deck adopts it); opening a theme tab freezes its base. A theme being edited is leased in the existing registry under a **theme scope**, so no other tab writes it meanwhile. One workspace request, `OpenTheme`, opens (or focuses) the tab right after the requesting tab; the "Packs du deck" theme row gets an "Ouvrir" button. Pack mode keeps its deck's theme and overrides: a pack working deck previews with them and refuses token ops. A theme tab persists only `state.json` (draft, tokens, written version): the specimen deck is rebuilt at resume.

**Tech Stack:** Rust 2024 (snafu, speculoos, rstest, nextest, OpenDAL `Storage`; clippy `pedantic`, `missing_docs`), React/TypeScript (Bun), Playwright e2e, Fluent.

**Spec:** `docs/superpowers/specs/2026-10-24-onglets-pack-theme-design.md` — "Sessions by document kind" (theme tab, `WrongDocument`), "Versions and adoption" (themes follow the same rule), "Lots" (lot 4) and its lot-3 implementation note; this plan's "Decisions" section amends the spec where they differ (Task 5 writes the amendment into the spec). ## Decisions (binding; the user's on 2026-10-26, the rest settled by this plan)

1. **Entry point (user):** lot 4 brings forward one of lot 6's entry points, an "Ouvrir" button on the theme row of "Packs du deck". Lot 6 keeps the packs' "Ouvrir" buttons and the app-menu entries.
2. **The theme draft leaves `Mode::Pack` for both hosts (user):** the in-deck workshop included. A pack working deck keeps its deck's `theme`, `themes` pins and `tokens` (overrides), with the theme versions they reach embedded, and renders through `compose_layer` like any deck. In pack mode, `SetToken`, `UnsetToken`, `SetTokens` and `SetTheme` ops are refused (`WrongDocument { kind: Pack }`). `save_pack` no longer saves a theme; `stash_adopt_theme` is deleted.
3. **`Mode::Theme`** holds `edit: ThemeTab { draft: ThemeEdit, parent: Option<PackVersion>, session_version: Option<PackVersion> }` (`parent`: the version the tab's writes descend from — the version opened, `None` for a new theme; kept apart from `draft.base` as `PackMode.parent` is, review B2), `switches: Vec<ThemeSwitch>` and `lease: Option<PackLease>`. Its working document is the specimen deck: slides = `layout_slides` of the built-in Essentiel (ids `layout-<name>`, `pack_mode.rs:87`), pins = built-in `base` and `essentiel` (`builtin_pin`), `theme: None`, `tokens` = the draft, `params.title` = the draft's name. **A theme tab never changes which theme it edits** (review B3): its base is fixed at opening; `Request::SetEditedTheme`, `set_edited_theme`, `drafted_theme_choice`, the `ThemeChoiceAlone` error (six edits removed, key in 20 locales removed) and the panel's base picker (`ThemePanel.tsx:58`) are deleted; `SetTheme` (op or request) is refused in a theme tab (`WrongDocument { kind: Theme }`): to start from another theme, the user opens that theme's tab. `ThemeSwitch` / `DRAFT_SWITCH_VAR` stay for `extends` edits only (and for the base move of a save, decision 5). **The op filter lives in `Session::apply`** (`deck_widgets.rs:303-320`, the choke point the MCP also calls; review M3): in a theme tab, a caller's ops must all be token ops (`SetToken`, `UnsetToken`, `SetTokens`), else `WrongDocument { kind: Theme }`; a `SetVar` of `DRAFT_SWITCH_VAR` is refused from any caller in every mode (`WrongDocument { kind }`), and the draft's own rank steps (`theme_extends.rs:121-122`) go through a private `apply_draft_step(label, ops)` that skips the caller filter.
4. **`WrongDocument { kind: DocumentKind }`** (`DocumentKind::{Deck, Help, Pack, Theme}`, the session's kind, serde snake_case) is the refusal of a request that makes no sense for the session's kind. **Requests:** a theme tab accepts exactly the `Request` variants that `Request::theme_tab_allows` (an exhaustive match, no wildcard, in `request_class.rs`) lists — `Snapshot`, `Slide`, `Search`, `Svg`, `Schema`, `Widgets`, `HostTheme`, `HostToken`, `Ui`, `Apply`, `Undo`, `Redo`, `UndoTurn`, `RenameEditedTheme`, `SetEditedThemeExtends`, `EditThemeExtends`, `SaveTheme` — and refuses every other with `WrongDocument { kind: Theme }` (`HostSettings`, `Layouts`, `Packs`, `WidgetStatus`, `WidgetSource`, `PreviewWidget`, `HistoryVersions` included: they serve elements, packs or files a theme tab has not). Outside a theme tab, the draft requests and `SaveTheme` are `WrongDocument { kind }` (they were `NotEditingPack`); `HostTheme` answers `null` as today. **Direct calls** (review M2: the agent calls session methods, `history.rs:180-183`): `ensure_editable` (`history.rs`) gains `Mode::Theme → WrongDocument { kind: Theme }`, so every agent-reachable mutator that guards with it refuses in a theme tab (`set_widget_by_agent`, `remove_deck_pack`, `save_copy_new`, merges, history…); `ensure_deck_mode` (`history.rs:197-204`) likewise; `new_deck` and `load` refuse in a theme tab as in a pack tab (`deck_file.rs:52-58`); the theme-tab paths (`apply` with token ops, the draft requests, `save_theme`, undo, redo, `undo_turn`) guard with `ensure_theme_tab` instead, never `ensure_editable`. `apply` runs `ensure_theme_lease` beside `ensure_pack_lease` (`deck_widgets.rs:305`).
5. **Saving (`Session::save_theme(as_new)`, `Request::SaveTheme { as_new }`):** an unchanged draft writes nothing and answers `null`. A changed user theme: the manifest's `parent` is `ThemeTab.parent` (never `draft.base`); under one `draft_lock`, `themes.draft_write(&lock, id, session_version)`; `New` → written as is; `Replace(v)` → replaces the tab's own unadopted draft (same parent, so `replace_version` drops `v`, `library.rs:520`); `Child(frozen)` → the files are **rebuilt under the lock** with `parent = frozen` (a theme counterpart of `rebased`, `pack_mode_save.rs:210-212`) and `ThemeTab.parent` becomes `frozen`; then `save_draft` (it makes it current). A child of a built-in, or `as_new`: a **new theme** (new id, namespace from its name through `library_namespace`, `extends` = the draft's list, no parent, the built-in's child named "(variante)" as today, a copy named by the new key `theme-copy-of` — `"{ $name } (copie)"` in fr, after `theme-copy-name` in the file holding it, 20 locales), written as `DraftWrite::New`, after the tab takes that new id's lease under the same `draft_lock` (`PackLease::try_take`); the tab then edits the new theme (`TabDocument::Theme` follows `tab_info`, `ThemeTab.parent = None`), its old lease drops. Either way the tab's draft becomes the saved version (`ThemeEdit::starting`), `session_version` = it, switches are remapped as `save_theme_edit` does today (`theme_draft.rs:174-185`), `doc.dirty = false`, and `save_theme` **persists the state itself** (review m2: `handle` skips `persist` when `changes` is false). `handle` answers the saved `ThemePin` as JSON, or `null`. The closure of the saved theme is checked before any write; the version bytes are computed before the lock except in the `Child` case. Saving never pins anything in a deck: decks see a new current version of their theme through "Packs du deck" (`ThemeSectionView.outdated`, recomputed by the `WRITES` count at their next snapshot); a new theme is picked from the theme menu (t-1207 offers it).
6. **Freezing:** opening a theme tab on a user theme, and resuming one that has not written yet, freezes its base (`themes.adopt(&lock, id, files)`, from the library's bytes); built-in and received versions are already frozen. A theme version is otherwise frozen only when a deck adopts it (`adopt_pins`, unchanged).
7. **Leases:** `LeaseScope` becomes an enum, `Packs { widgets, layouts }` (today's struct, `pack_lease.rs:40-53`) or `Themes { themes }`; `PackLibrary` computes both (`theme_scope()` beside `lease_scope()`, `library_packs.rs:66-76`, from its `themes` library's directory). A theme tab holds its theme's lease while awake; without it the tab is read-only (`ThemeTabView.read_only`): every draft request first retries `PackLease::acquire` and is refused with `ThemeOpenInTab { theme, tab }` while another tab holds it; it never autosaves on its own. `PackLease::try_take` (and so `acquire`) picks its refusal from the scope (review M4): `Packs` → `PackOpenInTab`, `Themes` → `ThemeOpenInTab { theme: name, tab }`; `SessionError::lease_holder` (`error.rs:504-510`) matches both. `edit_theme` (deck mode, `deck_theme_edit.rs:174`) refuses a theme leased by a tab (`ThemeOpenInTab`): the check, `add_version` and `set_current` (`deck_theme_edit.rs:220-221`) run under one `draft_lock`, released before `adopt_edited_theme` (whose `apply` → `adopt_pins` takes `DRAFTS`, `deck_adopt.rs:46`; review m9). The holder label of a theme tab is the theme's name (`pack_mode_lease.rs:52-55` `deck_label` gains the `Theme` arm). Leases stay process-local (lot 3's limit).
8. **No orphaned theme tab:** nothing deletes a library theme today; a theme tab whose theme or base version is gone from the library at resume is unreadable: the workspace shows `notice-tab-resume-failed` and keeps the folder aside (`Resumed::Unreadable`, `workspace_slot.rs:35-38`; review M7 — `notice-tab-set-aside` is only for older-version states).
9. **Resume:** a theme tab writes no `deck/` or `pack/`, only `state.json` = `{ version: 5, mode: {theme: ThemeTab}, ui, draft_tokens }`. Restoring checks: the cached document's theme id equals `draft.base.id`; the base version is readable (`theme_version`); the draft's namespace equals the base's (`ThemeBase`); `extends` passes `check_theme_extends`; `parent`, when set, is the base or an ancestor of it in the library (the check `check_pack_doc` makes, `resume_pack.rs:222-229`), and is `None` only for a theme whose base has no parent; `session_version`, when set, must equal `draft.base.version` (else cleared, logged); `draft_tokens` must be a JSON object within `MAX_JSON_BYTES` and pass the rule used when a theme is opened — **the paths that differ from the base's tokens** pass `check_token_ops_on` as one non-strict `SetTokens` (review m8: a received theme with tokens outside the specimen deck's schema opens, so it must resume too); the lease is retaken through `acquire` (refused: read-only, `notice-theme-edited-elsewhere`); an unwritten tab freezes its base (decision 6). **Legacy 6.0.0 pack states** — a version-3 workshop and a version-4 pack tab (review M1) — carry `theme_edit`, read as a legacy field (`#[serde(default, skip_serializing)]`), never applied: the restored working deck is restyled from its stash (the preview for a pack tab) by the same function `enter_pack` uses (theme, themes and tokens of the stash deck, the theme versions they reach embedded), applied with `apply_silent` (no undo step, `dirty` unchanged); the notice `notice-theme-draft-dropped` is shown only when that legacy draft differed from its base (the pure `draft_differs`, shared with `theme_dirty`). The next persist writes them at version 5.
10. **Opening (`WorkspaceRequest::OpenTheme { tab, theme }`):** `OPENING`, `OpeningSlot` and `with_opening` (private in `workspace_packs.rs:51-87`) move to a new `workspace_opening.rs` as `pub(super)`, used by both (review m5). Under `with_opening(theme)`: a tab whose cached document is `Theme { theme }` and whose live document agrees is focused; otherwise the requesting session checks the theme exists (`route_theme`, `UnknownTheme`; any tab kind may ask, a help tab included), the lease is acquired (refused: a live holder is focused, else `ThemeOpenInTab`), a pending tab `Opening::Theme { theme }` is placed right after the requester, built outside the workspace lock (`Pending::build_theme(lease)` → `Session::init_theme_tab`), finished and activated. The requester is the tab's opener in memory, so closing it activates the requester (lot 3's `detach_to_opener`); `PackOpener` answers `null` for a theme tab.
11. **UI:** a theme tab mounts the specimen pile (thumbnails, selectable, no add, delete, duplicate, drag or context menu), the stage (no element selection or field editing), the theme panel in the right column, and a header with the theme name and "Terminer" (closes the tab, saving first). The draft autosaves like a pack tab (`saveTheme`, only while leased); closing runs the close guard, saves, and offers to quit without saving when read-only and dirty (`ui-confirm-quit-read-only-theme`) or when the save still leaves it dirty (`ui-confirm-quit-theme`). The tab bar shows a "Thème" badge (`ui-tab-theme`) until lot 6's borders. The "Thème" sub-tab, `THEME_TAB` and its tests leave the pack tab. A theme tab has `editing: null`, so every UI place that reads `!snap.editing` as "a deck" also checks `snap.theming` (review M5): `DeckPile.tsx:47` (`fixed`), `ToolsTray.tsx:64` (no "Packs du deck"), `AppMenu.tsx:29` / `App.tsx:316` (no file entries: save, save as, history, import), `useAppKeys.ts:73,108` and `appKeyScope.ts` (no ⌘S, ⌘⇧S or slide keys), `useClipboard.ts:109` (no element paste), `useDataSettings.ts:37`; one `themeTab` flag computed in `App.tsx` is passed down. `deck.ts:365` `previewLook` reads `snap.theming?.theme` (and its `revision`) instead of `snap.editing?.theme`. The theme-tab panel has no base picker (decision 3).
12. **Smaller rules settled by the review:** a theme tab's `TabInfo.theme` is the edited theme's id (help opened from it takes that theme, `lib.rs:610-613`); `open_theme_here` with a refused lease opens read-only (the tests rely on it); the session rule "Pin base and essentiel where slides or elements are produced" adds the theme tab's specimen deck; the token schema in a theme tab covers the global tokens plus `base` and `essentiel`, narrower than pack mode's (which included the stashed deck's packs, `theme_composed.rs:53`): `component.<ns>` tokens of other packs are kept as they are but not shown or edited — a known limit written into ADR-0012 (lot 6's preview context may widen it). Every exhaustive `match` on `Mode` gains its intended `Theme` arm (review m6): `undo.rs:46` realign → `realign_theme_edit`; `widgets_edit.rs:209` and `:513-535` → refused (`ensure_editable`); `widget_preview.rs:175`, `add_grid.rs:88-90` → none (no previews, no add grid); `agent/turn_undo.rs:56-79` → the working deck, as in pack mode; `import/queue.rs:74-77` → refused; `help.rs:70,122` → like `Pack`; `history.rs:197-204` → `WrongDocument`; `theme_composed.rs:53,71` → the working deck only; `pack_mode_lease.rs:52-55` → the theme's name; `deck_theme.rs:388-392` (`stash_sources`) → `None`; `lib.rs:512,523,536,553,562,590` (`user_deck`, `user_blobs`… ) → the working document, as in deck mode.
