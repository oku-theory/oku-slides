# Data entities, phase 1 (data, table and chart views, Data panel) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Table and chart data become deck-level `Manual` data that views reference by id, so
several views share one data and a Data panel lists and edits data on their own. The model and
its bounds reach 65,536 × 1,000 cells; phase 1 reaches large data only by compacting edits into
a Parquet base (large imports are phase 2).

**Architecture:** A new crate `oku-slides-data` holds `Dataset`, the `Data` model (columns, row
ids, an optional Parquet base, a cell overlay in persistent `imbl` maps), its id-based edits and
the data bounds; its `engine` feature (polars `lazy`, `parquet`, `sql`) reads and writes Parquet
and is enabled only by the render worker, so Parquet is parsed only in the sandboxed worker.
`Deck.data` holds the data; the replica stores each as Loro containers that merge per cell, the
overlay inside a `layer` container replaced at each compaction (an epoch). `host(table|chart)`
options hold a `data` ref and optional `columns`. `prepare_ops` (core) draws every id and splits
inline data out of ops before each `apply`. The renderer resolves views (`Renderer::set_deck`):
each view's param gets its bounded `dataset`; render and Typst keep reading `dataset`. Bases live
in a content-addressed store on disk and travel in the sources zip; only the host compacts, on a
dedicated worker link. Paste is one stateless host request, `paste_element`.

**Tech Stack:** Rust (snafu, serde, schemars, time, imbl, polars 0.53 with `lazy`/`parquet`/`sql`,
loro 1.17.1 pinned), Fluent, React/TS (A2UI catalog), Bun.

**Spec:** `docs/superpowers/specs/2026-11-21-data-entities-design.md` (phase 1 only; its "Plan
calls" section lists this plan's choices; lists are phase 1b, queries phase 2, tags phase 3).

- Default data name: lowercased, accents stripped with `oku_slides_i18n::fold`, non-`[a-z0-9_]` runs → `_`, trimmed of `_`, leading digit → `_` prefix, empty → `data`, cut to 60 chars, duplicates (case-insensitive) `_2`, `_3`…; the source text becomes `label` via `clean_label`.

- Data name: `[a-z_][a-z0-9_]*`, 1–64 chars, unique case-insensitively. Label and column name ≤ 200 chars. SQL-reserved names allowed in phase 1.
- Column types: `text | number | integer | bool | date` (date `YYYY-MM-DD`, years 0001–9999; Parquet `Date32`). Number display: Rust `Display` of the `f64`, trailing `.0` dropped, `-0.0` → `"0"`, never the locale. `parse_number` (Task 2): optional leading `-` or `+` (U+2212 refused), digits, at most one `.` or `,` decimal separator, ≤ 15 significant digits (leading zeros not counted); input matching `^[+-]?[1-9]\d{0,2},\d{3}$` is refused as ambiguous (`"1,000"`, `"-2,500"`), so `"0,125"` → 0.125 and `"1,0000"` → 1.0; no grouping, exponent, surrounding whitespace, `inf`, `NaN`.
- Non-finite numbers in any input become `Null` and are reported (`data-non-finite`, `$count`), never stored.
- **Storage.** `Data { name, label: Option, inline: bool, kind: DataKind /* Manual */, table: Table }`, plain fields (no tagged enum, so the bounded visitors apply). `Table { generation, epoch (4f), columns, rows: imbl::Vector<String>, base: Option<BaseRef>, cells: imbl::OrdMap<CellKey, DataCell> }`; `CellKey` is `"<row id>/<column id>"`. `CellRead` = `Overlay(&DataCell)` (overlay entry) | `Cleared` (stored `Null`: base value hidden) | `Base` (no entry, base present) | `Null`. The overlay stores `Null` only when `base` is `Some`; without a base, `SetCell Null` removes the entry, and parse and replica read drop a stored `Null`. Concurrent `Replace`s or compactions resolve last-writer-wins; edits to the losing container are lost, deterministically, and reported (`MergeReport.lost`, `issue-data-edits-lost`).

## Review Focus

1. Two copies edit cells of one shared data (different cells, same cell, same row, same column), merged in both orders → both edits kept (same cell: one value, equal docs), each `SetCell` writes one Loro change (Task 3).
2. A cell edited in a data shared by a table and a chart → both resolved datasets hold the new value and the chart's SVG key changes, including a row beyond the table's 99-row cut and a data with a compacted base; an edit to a column the chart does not use leaves its key unchanged (4b, 4f).
3. Compaction (4f): a single 150,000-cell `AddData` step (`Origin::Host`), then edits → no compaction while an undo or redo step touches the data, every undo exact; past `MAX_OVERLAY` the data is folded at the current state, its undo steps dropped with a notice; a peer edit to the old layer merged in either order is lost on both peers and reported, docs equal.
4. Copy A removes a data while copy B binds a view to it; merged in both orders → failure frame, `issue-data-missing` names it, a sibling view still renders (Task 5).
5. Agent re-sets a chart three times with inline series, then a peer merges → one data, same id, replaced in place; one undo gives the second series, three undos leave no data (4b).
