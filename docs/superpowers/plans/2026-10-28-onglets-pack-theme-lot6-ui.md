# Packs and themes as tabs — lot 6: the interface — Implementation Plan (v3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pack tab looks and works like a deck tab: its items (widgets or layouts) fill the pile, the chosen item is in the sheet area with its tools; pack and theme tabs carry a coloured border; "Packs du deck" opens any pinned pack; the app menu creates a widget pack, a layout pack or a theme; a pack tab chooses its preview theme. The widget sub-tabs (`PackTabs`, `widgetTabs`, `PileWidgets`, `usePackWidgetEditor`) are gone.

**Architecture:** Backend: `Request::SetPreviewTheme` changes a pack tab's working deck theme **silently** (no undo step, not dirty, persisted); `WorkspaceRequest::{NewPack, NewTheme}` write an empty library draft under a short lease, then open it in a tab that records the created id (`TabInfo.created`), rolled back if the open fails and deleted by `Trash::empty` when its tab leaves for good with the library still holding only the creation version; each pack row of the packs panel gets an `open_pack` button the UI intercepts like `open_theme`; `UiState` keeps one selected item (`widget`). UI: `tabKind(snap)` picks the panels once; a pack tab's selection is `usePackItem`'s `selected` (a file name, `_commun` included), its `WidgetTab` shown alone.

**Tech Stack:** Rust 2024 (snafu, speculoos, rstest, nextest), React/TypeScript (Bun, happy-dom render tests), Playwright e2e, Fluent (20 locales).

**Spec:** `docs/superpowers/specs/2026-10-24-onglets-pack-theme-design.md` — "Tab model and resume" (the preview theme does not dirty the pack, l. 79-80), "Interface (`ui`)", "Testing", "Documentation", "Lots" (lot 6) and the lot 3-5 notes. ## Decisions (1-4, 6 and the choices in 2, 3 and 10 are the user's on 2026-10-28; the rest settled by this plan)

1. **App-menu entries (user).** "Nouveau pack de widgets", "Nouveau pack de layouts", "Nouveau thème" join the main menu; the `ui/AGENTS.md` settled decision on the menu is rewritten in Task 7 to name them.
2. **Creating from scratch (user: rolled back, deleted when untouched).** `WorkspaceRequest::NewPack { tab, kind }` / `NewTheme { tab }`:
   1. In one `Workspace::with_quiet(ws, tab, …)` call: the requester check, then the creation through the requester's library and localizer. `NewPack`: `Session::can_open_pack()` (`ensure_editable`, not a theme tab — the part of `route_pack`'s checks every pack open shares, extracted; `route_pack` keeps its own order and semantics) **and** a lease scope (`SingleDocument` otherwise: the creation needs one to write). `NewTheme`: any tab with a lease scope, as `OpenTheme`.
   2. The creation (`PackLibrary::create_empty_pack` / `create_empty_theme`), under one `draft_lock()`: namespace from `library_namespace(name, fallback)` (`fallback` = `pack` / `theme`, used when the localized name slugs to no letter; today `slug` always prefixes `pack-`, so it gains the prefix as a parameter), manifest with every field written out, a lease `PackLease::try_take(&lock, scope, id, …)` with `library.lease_scope()` (packs) or `library.theme_scope()` (themes, as `theme_tab_save.rs:95`) covering the write, `write_session_version(…, Some(&lease))` (packs) or the theme library's `save_draft` after the `covers` check (themes) — the same witness rule as every creating write — then the lease drops with the lock.
   3. Outside any lock: `open_pack_with(ws, tab, id, None, Opener::Ui, Created::Yes)` / `open_theme(…, Created::Yes)` (both gain a `created: Created` parameter, every existing caller passing `Created::No`; it travels in `Opening::Pack { pack, widget, created }` / `Opening::Theme { theme, created }` into `build_pack` / `build_theme` → `init_pack_tab` / `init_theme_tab`, set **before** `arm_resume` and before the `Tab` is inserted, so `state.json` and `workspace.json` carry it from the first write). **Only if that open returns an error, or an outcome other than `PackOpened::Opened(t)` / the new theme tab**, the draft is rolled back with `discard_untouched` (below); a later `view_json()` failure is returned without rollback (the tab exists).
   4. **The created id.** `PackMode.created_empty: Option<Uuid>` / `ThemeTab.created_empty: Option<Uuid>` (session state, persisted in `state.json`, `serde(default)`) and `TabInfo.created: Option<Uuid>` (from `tab_info()`, persisted in `workspace.json`, so a **dormant** resumed tab carries it too). It names the id created empty and is never cleared: a "save as new" moves the tab to the copy and leaves `created` on the original, so the original is still collected. Not `fresh`: `Session::is_fresh()` and `PackTabNotFresh` mean a pristine deck tab.
   5. **Deletion when the tab leaves for good.** Every tab that leaves the workspace for good ends in `Trash::empty` (`workspace_tabs.rs:33`: `close_tab` → `close_with_links`, `CloseWindow`, `apply`'s change arm, failed builds). For each gone tab whose `info.created` is `Some(id)`: after `stop_resume` and **after the tab (session and lease) is dropped**, outside the workspace lock, `discard_untouched(library, kind, id)` runs. It takes `draft_lock()`, then `PackLease::try_take` on the id (pack or theme scope); **refused → keep** (another tab or process holds it); granted → delete only if the library holds **exactly one version of that id** (the creation version; a version saved since — even if undone in the tab — keeps it), then release. A pack or theme already gone is `Ok` (the rollback and a failed build may both reach it). Under the workspace lock, when the gone list is built, a gone tab whose created id is still shown by a remaining tab of this process (`info.document`) has its `created` dropped first. `Closed::LastWindow` keeps its tabs (they resume), so nothing is deleted there.
   A deck that added the pack meanwhile keeps its embedded copy (embedded versions are authoritative). An empty pack has no files (`_commun` optional); an empty theme is `tokens: {}`, `extends: [<namespace of DEFAULT_THEME>]`. Opening freezes the base (`enter_pack` → `freeze_base`: an adopt marker, not a version), so the first save is a child of the empty version: decision accepted, pinned by a test. A crash between creation and open leaves an untabbed empty draft: added to t-1251.
3. **Preview theme (user: silent).** `Request::SetPreviewTheme { theme: String }` (a namespace; resolved by `find_theme`, `UnknownTheme` otherwise, as `Request::SetTheme`). Accepted only in a pack tab (library or deck-only): `ensure_fits` refuses it elsewhere with `WrongDocument` (history is refused earlier, `InHistory`). `Session::set_preview_theme` checks the pack lease like any edit (`ensure_pack_lease`: a tab whose lease another tab holds changes nothing; a tab that takes back a lease nobody holds freezes its base idempotently, as any first edit — the base was already frozen at open), then `apply_silent_ops`: the filled `Op::SetTheme` on a clone of the working deck, rendered, written by `sources.apply_silent` — **no undo step, `doc.dirty` untouched, no pack file, preview or real deck changed** — then persisted (`persist(true)`: `pack/` keeps the working deck, so it survives a restart). Spec l. 79's "default: the default theme of new decks" stays as lot 3 amended it: the opener's theme until changed.
4. **One lot (user).** Nine tasks, each committed after its review.
5. **New-pack requesters.** Menu: the two pack entries in deck and pack tabs (library and deck-only); "Nouveau thème" in deck, pack and theme tabs; none in help and history (they show no main menu entries beyond today's). A refused requester answers its error (`ReadOnly`, `InHistory`, `WrongDocument { kind: Theme }`, `SingleDocument`), nothing written.
6. **Duplicate and reorder deferred (user, t-1249).** The pile offers add, rename, delete. No context menu on pile items (t-1250).
7. **One selected item.** `UiState.widget` means "the selected item of a pack tab": `sanitized(true)` keeps it only if `WidgetFile::parse` accepts it (`_commun` included); the UI falls back when the current revision's statuses lack it. `UiState.widgets`, `MAX_WIDGET_TABS`, `make_room` and `PileSection::Widgets` are removed (Task 5, Rust and TS together); a saved `widgets` key or folded `widgets` section in an old `state.json` is ignored (serde without `deny_unknown_fields`; `kept_ui` drops unknown sections). Rename: F2 or double-click. 10. **Agent-written items.** A removal of the selected item selects its neighbour (as a delete) and shows `ui-widgets-removed-by-agent`, pending keystrokes dropped; a write to the selected item with pending keystrokes keeps them (`files.keep`); a write to another item selects it unless the selected one has pending keystrokes (then it only appears in the pile). Whether an agent write should move the selection at all is t-1253.
11. **Keys in a pack tab.** Inside the Typst editor CodeMirror handles ⌘Z / ⇧⌘Z; elsewhere in a pack tab they undo the session (example values, title, agent writes), as in a deck tab. ⌘W closes the pack tab (no sub-tab to close). Stage shortcuts, clipboard and stage anchors are off in any pack tab (`tabKind === "pack"`), selection or not.
12. **Tab kind.** `tabKind(snap)` → `"deck" | "pack" | "theme" | "help" | "history"`; `App` mounts `PackPanels` / `ThemePanels` / the deck's panels once per kind (the deck's stay in `App`, as today). `TabBar` reads the kind from `tab.document?.kind` (`documentKind`, exported from `tabKind.ts`).
13. **Borders.** `data-kind` on each tab (`pack` for `pack` and `deck_pack`); a 3 px solid top border in `--tab-pack` / `--tab-theme` (plain hex tokens, light and dark in `styles.css`; no `color-mix` tint, the active tab keeps today's active styling); `Icon.packs` before a pack tab's title, a new `Icon.palette` before a theme tab's, `aria-hidden`; the tab's accessible name is `ui-tab-kind-pack` / `ui-tab-kind-theme` = "{ $title }, pack" / "{ $title }, thème" (kind-neutral: `TabDocument` does not carry widgets vs layouts). `.tab-badge` and `ui-tab-pack` go; `ui-tab-theme` stays (`ThemePanel`, `ThemeTabHeader`).
14. **Packs panel "Ouvrir".** `PinnedPackView.id: Uuid`; each pack card's actions row starts with `{kind}/{ns}/open` (`packs-pack-open`), event `open_pack`, context `{pack: "<uuid>"}`; `packs_event` returns `None` for it, as for `open_theme`. The UI intercepts it in the tab **and in the detached agent window** (`panelOpen.ts`, replacing `themeToOpen.ts`), checks the id is a UUID, and calls `onOpenPack(pack, null)`. "Ouvrir" opens the library's current version (as `OpenPack` does); a deck-only pack opens its `DeckPack` tab.
