# List parameter `p.list`, entered as a table and editable on the slide — design

Date: 2026-10-04 · Task: t-494 · Follow-up: t-495 (nested lists)

## Goal

A widget that shows a list (timeline, row of KPIs,
team) simulates it today with flat parameters: `date1…date5`,
`texte1…texte5`, empty items hidden. The maximum is fixed, the dock
shows ten fields, and one can neither add, remove nor reorder
an item.

We add a **list** parameter type:

- declared by the widget with **typed columns** (`p.list(item: …)`);
- **entered as a table** in the dock (the table is only a way
  to enter the list; the slide shows it as the widget intends);
- **editable on the slide**: fields of each item, handles to
  add, remove and reorder;
- understood by the agent (ops, reading, writing widgets).

Out of scope: nested lists (t-495); slots in an item (an item
with free content is an element: `p.slot` with a child widget);
columns added by the user (the columns are those of the schema).

## Decisions

1. **New type `p.list`**, not a slot of child widgets: the widget
   receives the raw values and places them itself (date above the
   line, label below). A flow slot would only give it one finished `body`
   per child.
2. **Stable item ids**, generated by the host. Fields, handles,
   undo and the agent target an item by its id, never by its
   index: inserting or reordering moves no address.
3. **Allowed column types**: `plain`, `rich`, `number`, `flag`,
   `choice`, `asset`. Excluded: `slot`, `list` (t-495), `grid`, `host`.
4. **Reserved column names**: `id`, `kind`, and any name containing `/`.
5. **Address of an item field**: `<liste>/<id>/<colonne>`
   (`etapes/k3f9/date`), the owner remaining the element (or the slide).
   The interface's `fieldKey` does not change.
6. **Two write paths**: `Op::EditList` (insert, remove,
   move, modify a field) and `Op::SetParam` with the whole list
   (paste, replacement by the agent), reconciled by id.
7. **Undo through Loro**: no hand-written inverse; applying
   to the `Deck` then reconciling is enough.
8. **Dock**: a controlled typed table; `rich` column edited in a
   popover (`RichTextField`).
9. **Slide**: "+" handles between items and after the last one, "×"
   on the item, ⋮⋮ to drag along the axis, Alt+arrows on the keyboard.
   Shown only if the element is selected or one of its item fields
   is being edited.
10. **`item-label`** optional on the descriptor: feeds "Ajouter une
    étape" (Add a step), "Supprimer l'étape" (Delete the step) (argument of Fluent strings).

## Amendments after reading the code (2026-10-04)

These points take precedence over the sections that follow.

- **A1. Ids provided by the caller.** The core generates no id (element
  ids come from the interface, `newId` in `ui/src/deck.ts`).
  `ListOp::Insert` therefore carries the item's `id` (interface: `newId("i")`;
  agent: an id of its choice).
- **A1 bis. Absent = empty; the default seeds creation.** An empty
  array is indistinguishable from an empty `rich` once in JSON, and
  `canonicalize` removes empty values: an empty list is therefore
  **absent**, and an absent list is **empty** (Typst renders `()`). The
  schema's `default` only seeds a **new** object, declared by
  the caller — `add_element` and `add_slide` with `defaults: true`
  (creation from the library, or by the agent), `set_kind` that
  changes widget —, subtree included, with deterministic ids
  `d0`, `d1`… (`seed_lists`, core). A paste, a switch to grid or
  `replace_element` do not seed: they would bring back the default
  of an emptied list. The widget editor's
  preview shows the default (trial values absent).
  `set_param` to `null` empties the list.
- **A2. Replica container.** The replica read does without the
  registry and reads any parameter `LoroMovableList` as a slot.
  A list is therefore a `LoroMap { list: LoroMovableList<LoroMap> }`
  (like `rich`: `LoroMap { rich: LoroText }`), readable without the registry,
  created in advance (t-188 workaround); empty, it reads back as absent.
- **A3. Schema validation in Rust only.** `check_widget`
  (`SchemaFault`, translated messages) is the authority; Typst only adds
  `"list"` to `_types`.
- **A4. On-slide editing built in TS.** Field ops are
  made by `fieldOps` (`ui/src/deck.ts`): an item field there gives
  `edit_list { set_field }`. `FieldView` gains `list`, `item`, `column`.
- **A5. Dock: widget editor only.** The host dock sets
  widget parameters only in the widget editor (trial
  values); there is no element parameter dock in the deck.
  The table there modifies the trial values through a request
  `EditWidgetTrialList { name, param, change }`. In the deck, a list
  is edited on the slide and by the agent. TSV paste applies to the dock.
- **A6. `asset` column read-only in the dock**: the interface has no
  asset picker and `settable` already excludes `asset`. It is set
  by the agent (`edit_list`).
- **A7. Agent**: it reads slides as raw JSON (`SlideView`), items and
  ids included; no compact table. `ask_rewrite` stays limited to slide fields
  (`@titre`) and an element's first `rich`; the agent
  modifies an item field through `edit_list`.
- **A8. No context menu** on the stage: "×" only. "+"
  also **before the first** item (otherwise one cannot insert at the head).
- **A9. Shared grid** in `ui/src/table/` (`ui/src/grid.ts` already
  exists): TSV parsing and cell conversion. `ChartDataGrid` has
  no arrow navigation: native Tab, Enter moves down.
- **A10. Typst tests** in `crates/oku-slides-render/tests/` (no
  native Typst test runner).
- **A11. Base widget `frise`** added to `typst/oku-slides/src/widgets.typ`:
  acceptance case and e2e support (element added by `add_element`).

## Typst (`typst/oku-slides`)

**Descriptor** (`src/params.typ`):

```typst
/// List of items with typed columns; entered as a table in the dock.
#let list(label: none, item-label: none, item: (:), min: 0, max: none, default: ()) =
  _base("list", label, default) + (item-label: item-label, item: item, min: min, max: max)
```

`widget()` (`src/widget.typ`) adds `"list"` to `_types` and checks:
each column is a descriptor of an allowed type (3), no reserved name
(4), `min <= max`, `default` at most `max` items. Message for an excluded
type: "pour un contenu libre par item, utilisez `p.slot` avec un
widget enfant" (for free content per item, use `p.slot` with a child widget).

**Value received by the widget**: `args.etapes` is an array of
dictionaries `(id: "k3f9", date: "2019", texte: "Création")`; an absent
column takes its `default`.

**Helper** `list-item(ctx, name, it, body)` (`src/widget.typ`, exported
by `lib.typ`):

- `body` is a function `(c) => content`; `c` is `ctx` whose
  fields address the item: `field(c, "date", …)` emits the field
  `etapes/k3f9/date`. `field`, `fields-stack` and measuring do not change.
- emits, through `_measured`, a box `<oku-slides-item>`
  `(owner, list, item, index)`;
- `ctx.id == none` (preview without an owner): renders `body(ctx)` alone.

```typst
for e in args.etapes {
  list-item(ctx, "etapes", e, c => stack(
    field(c, "date", e.date), dot, field(c, "texte", e.texte)))
}
```

## Core (`oku-slides-core`)

**Schema** (`widget.rs`):
`ParamType::List { item: Vec<ParamSchema>, item_label: Option<String>, min: usize, max: Option<usize> }`,
with the checks of 3 and 4 when reading the schema.

**Value** (`params.rs`):

```rust
/// Items of a list (`list`): objects with an `id` and no `kind`.
ParamValue::List(Vec<ListItem>)
pub struct ListItem { pub id: String, pub values: Params } // serde: id + flatten
```

- Detection by shape: array of objects that all have a string `id` and
  **no** `kind` (an element has one). Empty array: current rule,
  and `Params::list(name)` reads an empty `Rich`/`Slot` as an empty list.
- Accessors `list()`, `list_mut()`, `lists()`, modelled on slots.

**Replica** (`replica/schema.rs`, `read.rs`, `write.rs`):

- `declared_kind(List)` → `Kind::Collection(Ctx::Item)` (new
  context): `LoroMovableList` of `LoroMap` with `id`, reconciled by
  `sync_list` (deletions, `mov` each in its own commit — t-263 —,
  insertions).
- In `Ctx::Item`: `id` → `Atom`; columns typed by the item's schema
  (`plain` → `Prose`, `rich` → `Rich`, others → `Atom`), otherwise by
  the shape of the value. The context must therefore carry the item's
  schema, as `Ctx::Params` carries the widget's.
- `fits(Collection, …)` accepts items (`is_items`) like elements.
- `declared()` creates the list in advance (t-188 workaround).

**Op** (`ops/mod.rs`, new `ops/list.rs`), modelled on `SetChartData`:

```rust
Op::EditList { target: Target, param: String, change: ListOp }
pub enum ListOp {
    Insert { index: Option<usize>, item: ListItemInput }, // id absent → assigned
    Remove { item: String },
    Move { item: String, to: usize },
    SetField { item: String, field: String, value: Value },
}
impl ListOp { pub fn apply(&self, items: &mut Vec<ListItem>, schema: &ListSchema) -> Result<ListChange> }
```

- `ListOp::apply` is **the** implementation, called by `Op::EditList`
  and by the widget's trial values (session).
- `Insert` fills absent columns with their `default` and returns
  the assigned id (`ListChange`).
- Translated Snafu errors: unknown item, unknown column, wrong
  type, `Insert` beyond `max`, `Remove` below `min`.
- `SetParam` of a list: values checked against the columns; absent ids
  assigned.

**Ids**: short, unique within the list; the items of `default`
receive them when the widget is instantiated.

**Validation** (`validate.rs`): empty or duplicate item ids, `min` and
`max`, column types, assets of `asset` columns present in the
sources.

**Fields** (`fields.rs`): `text_fields` inserts the `plain` and
`rich` columns of each item, in item order (Tab moves from one step to
the next).

## Rendering (`oku-slides-render`)

`Layout` gains `items: Vec<ItemBox>`, read from `<oku-slides-item>` like
`fields`; sorted by page. `SlideView` passes them to the interface.

## Session (`oku-slides-session`)

- A field with the address `liste/id/colonne` (on-slide editing, dictation,
  `ask_rewrite`) resolves to `EditList { SetField }`, with the merge
  key of a typing session.
- `widget_params::field`: `List` → `ParamField { kind: List, columns, value: items }`
  (`FieldKind::List` in `agent/forms.rs`); counts as one of the 8 fields.
- `host_param` event `{ key, change: ListOp }`: in the deck →
  `Op::EditList`; in the widget editor → `ListOp::apply` on the
  trial values (`set_widget_trials`).
- Insertion returns the created id to the interface (focus, see Slide).

## Interface (TypeScript)

**Dock** — `ui/src/a2ui/ListTable.tsx`, controlled component (TanStack
Table), no data modified locally:

| Column | Cell |
|---|---|
| `plain` | single-line input |
| `number` | numeric input, schema bounds |
| `flag` | checkbox |
| `choice` | select |
| `asset` | thumbnail; click → existing asset picker |
| `rich` | single-line preview; click → popover with `RichTextField` |

- "+ Ajouter <item-label>" (+ Add <item-label>) at the bottom (and Enter on the last row),
  disabled at `max` with a tooltip; "×" per row, disabled at `min`.
- Drag handle and Alt+↑/↓ to reorder.
- Tab / Shift+Tab from cell to cell, Enter moves down.
- TSV paste: from the current cell, columns in order,
  values converted to the type, missing rows inserted (up to
  `max`), invalid cells left and flagged; a single `SetParam`
  (one undo step).
- Typing: `SetField` with a merge key (one session = one step).
- Bounded height, internal scrolling.

**Shared by grids** — `ui/src/grid/`: keyboard navigation between
cells and TSV parsing, extracted from `ChartDataGrid`, which uses them
too. No single component: free columns and editable headers
on one side, typed columns on the other.

**Slide** — `ItemLayer` in `Stage.tsx`, next to `GridLayer`:

- Shown if the owning element is selected or if a field of one
  of its items is being edited; grouped by `(owner, list)`.
- "+" between two items and after the last one (`Insert { index }`),
  hidden at `max`; "×" at the corner of the hovered or focused item, hidden at
  `min`, and "Supprimer <item-label>" (Delete <item-label>) in the context menu.
- ⋮⋮ on the hovered item: drag along the axis, drop marker
  between two items, then `Move`. Alt+←/→ or ↑/↓ from a focused field.
- Axis deduced from the item centres; a single item: "+" on the side where the
  element's frame has the most room.
- After an insertion: focus on the new item's first text field
  (`fieldKey(owner, "etapes/<id>/date")`), text selected. A click
  on the box of an item without a measured field focuses its first field.

**Labels**: new Fluent strings (add, delete, limits,
errors) in **all** the present languages; `item-label` is only
an argument of them, otherwise a generic label ("un élément", an item).

## Agent

- `edit_list` comes from the generated JSON schema of the ops; its doc says to address
  items by id and to use `set_param` to replace everything.
- Reading a slide: a list shown as a compact table, one row
  per item with its id (`k3f9 · 2019 · Création de l'entreprise`).
- Fields: the tools that take a field accept `etapes/k3f9/texte`.
- Writing widgets: the widget editor instructions and
  `typst/oku-slides/README.md` document `p.list`, `list-item`,
  `item-label`, the allowed types, with the timeline as an example.
